# Changelog

## 0.2.2 — 2026-11-15

Cost has a shape, and reading it wrongly fails quietly. This release names the
shape, detects it once, and writes the rule down for the two other things that
were also being assumed: what a sub-agent is called, and how many ways one
model may cover.

### Added

- **`enbanc scoring`** — detects whether a panel publishes a credits
  multiplier or per-token prices, records the answer in `scoring-mode.json`
  under `ENBANC_HOME` (default `~/.enbanc`), and reads that record on later
  runs. `--models <file>` detects from a listing, `--mode` forces a shape,
  `--refresh` re-probes after a panel change. `doctor` prints the recorded
  state as one `scoring:` line and stays offline.
- **`src/enbanc/scoring.py`** — blend (`3:1` prompt:completion, cache reads
  excluded), relative rate against an anchor, coverage-based detection with an
  explicit floor, and a note when neither shape covers the list. A published
  `0` is treated as a price, so free tiers stay free instead of drifting to the
  expensive end.

### Changed

- **Sub-agent names must be readable.** The display name is generated by the
  host as `<type>-<index>`; the task-level name does not reach it. `SKILL.md`
  now asks for role-named custom sub-agents in the user's language, and for an
  explicit "card names are not controllable, use this table" note when the host
  cannot do it — instead of a column of `general-purpose-1/2/3`.
- **Model reuse is classified before it is capped.** Partitioned work (each
  path produces an interchangeable block, nobody reads the others) may put any
  number of paths on one cheap model. Complementary or sequential work
  (produce→review, upstream→downstream, different faces of one artifact) caps
  at three paths per model. The first limit is about cost, the second is about
  independence: several paths on one model agree because they share its bias.
- **Time-of-day tiers are gone.** Cost comes from the panel, not from a clock.

### Why

A ranking that silently loses its cost term keeps producing plausible orderings
while it has stopped discriminating — the failure is invisible in the output and
invisible in the logs. Naming the shape, detecting it once, and recording the
decision turns that into a readable state a person can check.

## 0.2.1 — 2026-11-13

The primary README is now written in Chinese, with English kept as a
switchable translation, and the release gate points the same way.

### Changed

- **`README.md` is Chinese; `README.en.md` is the translation.** GitHub shows
  the primary file, so the repository opens in the language the project is
  written in. The line under the title switches between the two, and the parity
  check reads in that direction as well: every mechanism label in the Chinese
  text must appear in the English one.
- **The contact address is allowed in the translated README.** The privacy
  allow-list named the old file; a translation that cannot carry the public
  contact would have to drop it silently.
- **The quick-start block no longer trips the quantity gate unannounced.** The
  demo closes a single-producer run at `P5`, which the gate added in 0.2.0
  refuses; the command now carries the waiver and the prose says why.

### Why

A repository whose main text is a translation reads like documentation written
for someone else. The gate had to move with it: a parity check that only looks
for English literals inside Chinese text stops meaning anything once the two
swap places.

## 0.2.0 — 2026-11-13

Four gates against the ways a run fakes progress: work that was never split,
a review that cost a few tokens, parallelism nobody derived, and a run
nobody watched.

### Added

- **A quantity gate with a solo waiver.** Entering `P2`–`P5` with fewer than
  two dispatched tasks is refused by default: work that was never divided
  cannot have been seen by anyone else. The waiver is explicit —
  `--allow-solo --reason "<why one worker suffices>"` — recorded in
  `state.solo_waiver` and surfaced in the delivery summary's degradation
  section. `--force` still crosses the gate, but writes
  `force_skip_quantity_gate` as it does, so forcing is countable, never
  silent.
- **A review-usage gate.** A reviewer that spends a handful of tokens to
  answer `pass` has not reviewed anything. When the reviewer reports
  `completion_tokens` below a threshold (default 120) and the verdict is
  `pass` or `conditional_pass`, the verdict is rewritten to
  `insufficient_review` and treated as a failure — it cannot reach `P5`.
  Whether usage is reported at all is the provider's decision, so a missing
  report is not an offence by default; only an explicit `--require-usage`
  turns absence into failure. Without evidence the run marks the review
  unverified rather than asserting laziness.
- **Write-set parallelism.** Tasks may declare the paths they write
  (`writes`). The scheduler groups by conflict: disjoint write sets run in
  parallel; overlapping ones — the same file, or one path inside the
  other's directory — share a group and run serially. Two tasks with no
  declared write set that target the same output file are refused before
  dispatch: serial is not a licence to overwrite.
- **An external inspector.** The main session is not a trustworthy monitor:
  it gets compacted, interrupted, and displaced by the next task. The
  inspector is a separate read-only pass — run once, read once, print,
  exit — and changes no state. It alarms with exit code 10 on `no_state`,
  `stalled`, `zero_sub`, `thin_review`, `zombie` or `bad_state`, and runs
  at three fixed points: after decomposition, before delivery, and once a
  day.

### Why

All four close the same failure shape: a run reporting progress nobody
verified. Work that was never split cannot have been independently seen; a
review that cost a handful of tokens is a stamp, not a check; parallelism
decided by hand collides silently; and a run left unwatched drifts while
the session that owned it moves on. Each gate turns one of these into
something countable on disk instead of something assumed.

## 0.1.4 — 2026-11-10

A sub-agent that inherits the main model is indistinguishable from the main
session afterwards. Say which model you dispatched, and say it when you do.

### Added

- **Every dispatch declares its model, and every dispatch is reported back.**
  A sub-agent without an explicit model usually inherits the main session's
  model — same model, same rate — so afterwards the usage statistics cannot
  tell a genuine fan-out from a single session talking to itself. `P1` now
  requires an explicit model per sub-agent, a stated fallback ("inherits the
  main model") when the host cannot choose one, and an immediate receipt table
  with one row per dispatch: index, sub-agent, model, work title, expected
  output.
- **A receipt that does not match reality counts as a failure**, and is
  reported in the delivery summary.
- **Self-review by the main model is not independent review.** When the
  reviewer shares the main model's family, the run may only claim
  "same-model independent context check" — never cross-model verification.

### Why

A user reading token usage concluded no sub-agents had been dispatched at all.
Nothing was broken in the accounting: the sub-agents were running on the main
model precisely because no model was named, which is exactly what makes them
invisible. The fix is disclosure at dispatch time, not better bookkeeping
afterwards.

## 0.1.3 — 2026-11-08

A pass with open findings is no longer a pass. Three outcomes, three exits.

### Added

- **`conditional_pass` is its own verdict.** A judge that returns `pass` while
  still listing findings used to be recorded as a pass; the delivery gate only
  read the verdict, so runs shipped with known defects and the report said
  "passed". Now `pass` + findings normalises to `conditional_pass`, and
  `stage --set P5` refuses unless the caller passes `--accept-residual`.
  Accepted runs record `outcome=accepted_with_residual` plus the residual
  findings, so "shipped with known defects" is countable after the fact.
- **Derived state treats it as `needs_human`**, not `idle` — fixing or
  accepting is a person's decision, not the orchestrator's.

### Why

Two real runs (`p2-closeout`, `rack-pdu`) passed with one or two open findings
and were reported as delivered. The information was in `review-rN.json` the
whole time; nothing read it at the gate.

### Documentation

- The READMEs were rewritten around what the tool does, where it fits, and how
  it works, instead of why it was started. The "Why I made it" section is gone;
  "What it can do" replaces it, and the author page now describes how the
  implementation was actually assembled.
- `docs/reference/rules.md`, `docs/001-model.md` and `docs/003-operations.md`
  now describe the three verdicts and the `accepted_with_residual` outcome.
  `docs/000-why.md` keeps the original audit but points at the current rules.
- Both READMEs are 178 lines and share the same section order, tables and links.

### Tests

3 new smoke tests pin the outcome: `pass` + finding becomes `conditional_pass`,
delivery is refused without explicit acceptance, and the accepted run records
its residual. 62/62 pass with `python tests/run.py`.

## 0.1.1 — 2026-11-06

Two fixes for state that described itself incorrectly. Both came out of
auditing real runs, not out of reading the code.

### Fixed

- **The delivery record is revocable.** A run that passed early and then came
  back `revise` kept `outcome=completed` forever — the field said delivered, the
  derived state said `needs_human`, and anything reading the field believed the
  run was finished. A non-passing review now clears the record and writes
  `outcome_revoked` with the reason; a re-review that passes while the cursor is
  already at `P5` restores it.
- **A pass with open findings is labelled.** `render` appends `, N open` when
  the final verdict is `pass` but findings remain, and `stage --set P5` prints
  them. Low-severity deferred work is allowed; being quiet about it is not.
  `docs/reference/rules.md` §2 documents both rules.
- **Nothing to review is refused.** A review with an empty or missing artifact
  set used to return `pass` — the judge was answering an empty payload. Three
  audited runs reached delivery with an empty directory that way. `review()` now
  raises before calling a judge, and `set_stage("P5")` refuses delivery when no
  non-empty artifact exists (force still works, with a reason).

## 0.1.0 — 2026-11-05

First public release.

### Workflow

- **Derived state.** Eight states computed from evidence on disk. The stage
  cursor is separate and cannot by itself mark a run delivered.
- **Delivery gate.** `P5` requires a passing verdict, or an explicit forced
  stop with a reason.
- **Report contract.** `ready` is the only path to `done`; text without a report
  is `unverified`.
- **Verifiers.** `document`, `page`, `deck`, `code`. Mechanical findings outrank
  a judge's opinion.
- **Escalation chain.** Each judge gets one shot; exhaustion produces
  `needs_human` rather than a lowered bar.
- **Idempotent dispatch.** Re-dispatching the same round is a no-op.
- **Mandate.** Scope is checked mechanically, with `unavailable` reported
  instead of guessed when there is no ground truth.
- **Routing.** Findings go back to the task that owns them; unmatched findings
  are surfaced, not guessed.

### Packaging

- Self-contained WorkBuddy skill using host models and relative resources; no
  author gateway, model matrix or credentials are required.
- Optional offline environment checks, and a minimal skill ZIP export containing
  the public instructions, safety rules and MIT license.
- Positive public-file list, index and history checks, and mandatory checks
  before push; sync state and logs stay local.
- CLI environment inheritance limited to system essentials plus explicit
  settings.
- General safety rules, privacy limits, and contribution and contact
  information.

### Repository

- Issue and pull-request templates, and a private security reporting path.
- CI on Python 3.10, 3.12 and 3.13: run the tests, install the package, smoke
  the console script.
- The publish gate now admits `.github/` Markdown and workflow files. They go
  through the same privacy scan as every other file; the allow-list was widened,
  not bypassed.

### Known gaps

- no cost tracking; that belongs in the provider adapter
- no render step for visual artifacts; structural checks only
- one process, no distributed workers
- account-based cloud calls and desktop skill import are untested here; offline
  tests are not evidence of model entitlement
