# 隐私边界与发布检查

## 自用配置与公开内容分开

本机自用配置可以保留用户自己的端点、模型与路径；公开仓库不复制它们。可移植性来自默认模型、当前工作区、相对资源与用户自己的授权，不来自把私人值替换成无法运行的占位符。

本次审查只针对此仓库和指定自用技能的数据流，没有读取真实凭据目录或账户认证文件。以下为静态审查与合成数据测试结论，不是零泄漏承诺，也不是对未知历史文件的背书。

## 本次修正

| 原先的缺口 | 现在的处理 |
|---|---|
| 整个同步目录不扫描，里面却可能落私人目录与章节信息 | 发布脚本本身纳入检查；同步状态仅存摘要，不保存绝对路径、标题或正文；状态被 Git 忽略 |
| 推送入口没有强制调用检查 | 推送前必须通过文件、隐私、暂存、可达本地历史、测试与 README 检查；没有跳过参数 |
| 只检查有限后缀，日志和未知文件可能漏过 | 公开文件采用正向白名单；未知类型失败；检查 UTF-8 内容，不仅按扩展名 |
| 已删掉的秘密仍可能在历史提交中 | 检查本地分支、标签及其可达提交内容和元数据；已跟踪的忽略文件仍拒绝 |
| 诊断输出匹配值 | 只输出相对位置与风险类别，不输出密钥、地址或正文 |
| 公共版本只有 Python 包，没有独立技能入口 | 增加不含私人配置的 `SKILL.md` 与规则资源，宿主模式默认采用用户自己的模型和工具 |

## 检查范围

公开白名单包括 README、许可、包配置、源代码、测试、文档、公开技能入口与安全规则。运行目录、日志、环境文件、同步状态、构建目录和导出 ZIP 不属于 Git 发布内容。已经进入索引或历史的禁止路径不能因为后来补 `.gitignore` 而获得豁免。

检测覆盖地址、用户路径、常见密钥与凭据赋值、私钥、私有模型标识及不允许的文件类型。检查失败时先定位并处理，禁止使用直接推送绕过脚本。浅历史、特殊替换历史等无法完整验证的情况拒绝发布。

作者明确同意公开的联系邮箱，只允许在两份 README 的联系段及本隐私文档中出现。它是主动公开信息，不是密钥；这不放行其他邮箱、联系方式或机器信息。公开邮箱可能收到垃圾邮件，请不要发送口令、原始日志或保密材料。

## 运行时的数据流

公开技能本身不读取个人记忆、配置密钥或全部环境变量，不写作者机器状态，也不回连作者服务。它会使用用户当前宿主；材料仍可能发送给用户选择的云模型，不应称为完全离线或不会外发。

Python 的 mock 路径仅在本机运行。通用 CLI 适配器会启动用户指定程序，启动程序仍可能读取其自己的宿主设置、认证存储或执行工具。项目内的环境白名单不是系统沙箱，不能阻止该程序访问用户文件；必须同时管理宿主工具权限与授权范围。不要给不可信 CLI 授予凭据或连接器。

模型返回与产物可能含本地路径、账号等敏感片段；运行记录默认留在本机，分享前仍要人工复核。提示词中的规则不保证模型服从，检查脚本也不能识别所有个人或商业秘密。

## 还不能保证什么

- 不对图片、Office 文件、音视频或其他二进制元数据宣称自动审计；当前发布白名单拒绝未知二进制。需要加入时先增加专门检查与人工复核。
- 不承诺发现没有已知模式的私人域名、编号、业务信息或加密秘密。
- 不改写已经推送的远端历史，也没有在本次操作中读取远端仓库。本地尚未初始化 Git，首次发布后需继续在真实仓库上使用同样门禁。
- Git 提交身份的姓名与邮箱也是公开元数据；首次提交时由作者选择公开身份或平台提供的 noreply 邮箱，不能复制操作系统默认身份。
- 本次未实际用普通账户调用云模型，也未导入 WorkBuddy 客户端执行 Office 任务。无自定义模型的可用性有官方能力依据，实际账户授权仍需下载者确认。
